# Concurrency Control Specification (P0)

> **Status**: Approved
> **Objective**: Prevent race conditions, ensure idempotency, and guarantee data consistency across distributed workers.

## 1. Race Conditions (Worker Conflict)

**Scenario**: Two workers try to update the same User Profile simultaneously.

### 1.1 Distributed Lock (Redis)
All write operations to Shared State (LTM/Profile) must acquire a lock first.

*   **Key Pattern**: `lock:profile:{user_id}`
*   **Mechanism**: `SET NX EX 10` + lease renewal heartbeat (every 3s) + **Fencing Token** (Monotonic Counter).
*   **Logic**:
    1.  Acquire Lock -> Get `fencing_token`.
    2.  Start heartbeat to extend lock TTL while task is active.
    3.  Write to DB with `WHERE version < fencing_token`.
    4.  If DB Rows Affected == 0 -> Conflict (Stale Write) -> Retry.

---

## 2. Idempotency (Message Deduplication)

**Scenario**: NATS delivers the same "Chat Log" message twice.

### 2.1 Event ID Tracking
*   **Trace ID != Event ID**: Use `event_id` (UUIDv7 generated by Producer) as the unique key.
*   **Storage**: Redis Set `processed_events:{hour_bucket}`.
*   **Logic**:
    1.  Worker receives msg `event_id_123`.
    2.  Check `SISMEMBER processed_events:current event_id_123`.
    3.  If exists -> ACK and Skip.
    4.  Process -> `SADD processed_events:current event_id_123`.
    5.  Set TTL = 24h on hour bucket key.

---

## 3. Queue Reliability (ACK Mechanism)

**Scenario**: Worker crashes mid-process.

### 3.1 NATS JetStream Config
*   **AckPolicy**: `Explicit` (Worker must manually ACK).
*   **MaxDeliver**: 5 (Retry 5 times).
*   **AckWait**: 30s (If no ACK in 30s, re-deliver).

### 3.2 Dead Letter Queue (DLQ)
*   **Trigger**: If `delivery_count > 5`.
*   **Action**: NATS automatically moves message to `stream.dlq`.
*   **Recovery**: Admin inspects DLQ and replays messages after fixing bug.
